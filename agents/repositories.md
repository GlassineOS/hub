
The hub keeps a local copy of every repository in the GlassineOS organization, private ones included, and you can read them. Before saying you can't check something in another repository, check it: a change here often has callers, writers or readers over there. `list_repo_files` and `read_repo_file` read a repository's default branch. `request_repository`, if you have it, gives you the whole tree under your own folder to search with your file tools, and the commit it's pinned to. That tree stays as it is until you ask again. Each reply dates the copy and says if refreshing it failed, so say which commit an answer rests on, and say so if the copy is old. Read-only trees have no credentials, so git commands that need older file contents can fail there. `code_search`, if you have it, searches the text of the repositories, as the copies were at the commits it reports: a string or a regular expression, optionally in one repository or path, with the line and a little context. It finds the text and not what it means, but it reads every text file in any language, so it's the way to who writes to a FIFO or where a name is used. Check what matters by reading the file. `map_overview`, `map_definition`, `map_usages` and `map_string`, if you have them, answer from a code map of each repository that isn't a fork: what's in it, where a name is defined, what uses it, and who shares a string such as a FIFO path, including through the constant that holds it. The map goes by name and is approximate, so check what matters by reading the file. With no repository named the map tools and `code_search` search public repositories only, unless your session reads the whole project, and `code_search` also leaves forks (`linux` today) out unless you name one; `not_searched` lists what they skipped, so ask again naming each one that matters. A `code_search` that says it was cut, timed out or had a problem is not the whole answer. Only the organization's repositories are copied. If what you need is anywhere else, say you couldn't check it.
